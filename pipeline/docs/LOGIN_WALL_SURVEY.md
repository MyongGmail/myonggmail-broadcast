# 로그인벽 탐사 계획 (LOGIN_WALL_SURVEY)

> 질문: **로그인해야만 보이는 공지가 얼마나 되는가?** 로그인벽 뒤 플랫폼의 공지가 공개 게시판에도 교차 게재된다면 현행 공개 크롤만으로 충분하고, 단독 게재가 많다면 별도 대응(수동 모니터링 승격·학교 협의)이 필요하다. 이 문서는 그 판단 근거를 만드는 탐사의 계획과 결과 틀이다.

## 대상

| 플랫폼 | 주소 | 성격 | 공개측 대조군 |
|---|---|---|---|
| MYiCAP+ | myicap.mju.ac.kr | 비교과 통합(교육인증센터 운영) | `cap`(교육인증센터 공지)·`mjukr-5364`(학생활동)·@mju_cap |
| MyiWeb·MSI | 학교 포털 | 학사 행정 포털 내부 공지 | `mjukr-257`(학사공지) 등 본부 게시판 |
| LMS ASTRA | LMS | 수업·학습 공지 | (수업 단위 — 대조군 없음, 범위 판정용) |
| 미래융합대 CDPS | 미래융합대학 시스템 | 성인학습자 비교과 | `future`(미래융합대학 공지) |

## 방법

1. **사용자가** Chrome에서 학교 SSO로 각 플랫폼에 로그인한다 (크롤러는 로그인벽을 넘지 않는다 — 계정 자동화 금지).
2. Claude가 chrome extension으로 열린 화면을 **읽기 전용** 탐사: 공지/프로그램 목록의 제목·게시일·주관부서를 표본 수집. 클릭 이동은 목록·상세 열람까지만, 폼 제출·설정 변경 없음.
3. 표본별로 공개 게시판(위 대조군 채널, 이미 `notices_v2.json`에 적재됨)과 제목 대조 → 교차 게재 여부 판정.
4. 결과를 아래 결과 섹션에 기록.

## 측정 목표

- **MYiCAP+ 단독 게재율** = (MYiCAP+ 목록 표본 중 공개 게시판 미게재 건수) / (표본 수). 핵심 지표 — 이 값이 높으면 비교과 공지의 상당수가 현행 파이프라인 사각지대라는 뜻.
- MyiWeb·MSI: 포털 단독 공지의 존재 여부와 성격(행정 공지인지, 학생 대상 프로그램인지).
- LMS ASTRA: 전교 공지 게시 여부만 확인(수업 단위 공지는 범위 밖 판정 예상).
- CDPS: `future` 채널 대비 단독 게재율.

## 판정 기준 (탐사 후)

- 단독 게재율 낮음(대부분 교차 게재) → 현행 공개 크롤 유지, 해당 플랫폼은 분기 표본 점검으로 격하.
- 단독 게재율 높음 → [MONITORING_CHECKLIST](../../docs/MONITORING_CHECKLIST.md) 주간 항목으로 승격 + 운영 부서(교육인증센터 등)와 공식 제공 경로 협의 검토.

## 결과 (2026-07-18 실시 — 사용자 SSO 세션 + Claude chrome extension 읽기 탐사)

### MYiCAP+ (핵심)

| 항목 | 값 |
|---|---|
| 탐사 일시 | 2026-07-18 |
| 목록 구조 | `/site/reservation/lecture/lectureList?menuid=001002002&reservegroupid=1` — 페이지 파라미터 `currentpage`, 10행/페이지. 상세는 `menuid/reservegroupid/lecturegroupid` 파라미터. 연번(No.) 7719 = 시스템 누적 프로그램 수 |
| 표본 수 | 40건 (No.7680~7719, 신청기간 2026-05-28~07-16의 약 7주치) — `pipeline/snapshots/state/myicap_sample_2026-07-18.json` |
| 공개 게시판 교차 게재 | 28건 (자동 제목매칭 20 + 우산공지·표기차 수동판정 8) |
| **단독 게재율** | **9/40 = 22.5% 확정, 보류 3건 재판정 후 사실상 12/40 = 30%** — 학과 35개 크롤 가동 후 재검(2026-07-18): 학술제(dept-3e)는 후속 글만 있고 모집 공지는 MYiCAP+ 단독, 경영대 기업탐방·법조실무연구회는 해당 학과 게시판 자체가 미커버(GNB 홈페이지 링크 부재)라 공개 지면 부재 |
| 판정 | **단독 게재율 유의미 — 공개 크롤만으로는 비교과의 약 1/4 누락.** 아래 후속 대응 참조 |

핵심 관찰:
- 단독 게재 9건 전원이 **취업지원 계열 부서**(MJ대학일자리플러스센터·인문/자연진로취업지원팀) 프로그램 — 이 부서들은 상세 모집글을 MYiCAP+에만 올리는 관행이 있음 (예: 실전 면접, SPEC 다듬기 시리즈, 숏폼 포트폴리오, 금융사기 예방 교육).
- 교차 게재 시 **우산 공지** 패턴: 게시판 공지 1건이 MYiCAP+ 프로그램 여러 건을 묶음(현.생특강 3건 ← mjukr-260 공지 1건). 제목만으로는 매칭 불가, 본문 내 myicap 링크로 매칭됨 → **상세 본문 수집이 매칭 정확도에 필수**.
- MYiCAP+는 robots.txt 전체 Disallow + 전면 SSO — **자동 크롤은 크롤러 예절 원칙 위반이라 배제**. 수집하려면 운영주체(교육인증센터 cap@mju.ac.kr) 공식 협조가 정도(正道).

### 후속 대응 (판정 기준 적용)

1. MYiCAP+를 [MONITORING_CHECKLIST](../../docs/MONITORING_CHECKLIST.md) **주간 항목으로 승격** — 신청가능/신청대기 목록 1~2페이지를 사용자 세션에서 눈으로 대조.
2. **교육인증센터에 공식 데이터 제공 협의 타진** (인수인계 전제와 부합 — 학교에 넘길 서비스이므로 명분 충분). 협의 성사 시 S2 어댑터 추가로 단독 게재분 해소.
3. 단독 게재가 취업 계열에 집중되므로 mjujob 어댑터의 `course_list.jsp`(프로그램 과정 목록) 커버 확장을 우선 검토 — 공개 지면에서 회수 가능한 단독분이 있는지 확인.
4. 학과 게시판 레지스트리(~60개) 크롤 가동 후 보류 3건(학과 주관 학술제·기업탐방·멘토링) 재판정.
